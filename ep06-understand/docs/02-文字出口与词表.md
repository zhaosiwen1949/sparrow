# 02 · 文字出口与词表:麻雀怎么「说」出标签

[01](01-从输入到标签全链路.md) 讲到主干的输出。本篇讲最后一步:`text_head` 在每个位置为 27 项打分,训练时把正确项的分数推高,回答时逐格选最高的那项。这部分代码全是第 2 集写的,第 4 集没有改动;第 6 集是它第一次被真正训练。

[README](../README.md) 第 4 节里的几个说法,在代码里分别对应:

| README 的说法 | 代码 |

| 「词表固定为 8 个颜色、6 个动物、4 个动作和 9 个记号,共 27 项」 | [parts.py:10-17](../code/parts.py#L10) 的 `VOCAB` |

## 1. 27 项词表〔ep02 已有〕

[parts.py:10-17](../code/parts.py#L10)

```python
COLOR_ZH = {"red": "红色", "orange": "橙色", "yellow": "黄色", "green": "绿色",
            "blue": "蓝色", "purple": "紫色", "pink": "粉色", "brown": "棕色"}
ANIMAL_ZH = {"cat": "小猫", "dog": "小狗", "rabbit": "小兔", "bird": "小鸟", "fish": "小鱼", "bear": "小熊"}
ACTION_ZH = {"run_left": "向左跑", "run_right": "向右跑", "jump": "跳", "turn": "转身"}
SPECIAL = ["<bos>", "<eos>", "<null>", "<img>", "</img>", "<aud>", "</aud>", "<vid>", "</vid>"]
VOCAB = [颜色 8 个] + [动物 6 个] + [动作 4 个] + SPECIAL
```

| 编号 | 内容 | 在哪些模板里出现 |
|---|---|---|
| 0-7 | 红色 橙色 黄色 绿色 蓝色 紫色 粉色 棕色 | 生成题的条件;i2t、v2t 的答案 |
| 8-13 | 小猫 小狗 小兔 小鸟 小鱼 小熊 | 生成题的条件;三道理解题的答案 |
| 14-17 | 向左跑 向右跑 跳 转身 | t2v 的条件;v2t 的答案 |
| 18 | `<bos>` | 全部模板的开头 |
| 19 | `<eos>` | 只在理解模板里,作为最后一个答案 |
| 20 | `<null>` | 生成题训练时 10% 去掉条件、生成时的无条件那一路 |
| 21-26 | `<img>` `</img>` `<aud>` `</aud>` `<vid>` `</vid>` | 开标签:生成和理解都用;闭标签:只在理解模板里 |

这是一张**标签清单**,不是分词器:「向左跑」整体是一项,中文不再拆字。词表在代码里写死,训练只改参数,不会增删词表项,也不会改标签文字。

`text_head` 在**每个位置**都输出 27 个分数(`[B, L, 27]`),不会先按「这一格该填颜色」筛候选。所以没训练好的模型可能在颜色格说出 `<vid>`,在 `<eos>` 格说出「跳」(见第 4 节的实例)。

## 2. 答案位与注意力掩码〔ep02 已有〕

`Layout` 处理模板里的文字项时([sparrow.py:161-172](../code/sparrow.py#L161)):

```python
w = item.rstrip("*")
if w in ("C", "A", "T"):
    slots[w] = s                       # 颜色/动物/动作的空位
tok.append(ID.get(w, 0))               # 固定词填它的编号;空位先填 0
answer.append(item.endswith("*"))      # 带 * 的是答案位
```

于是三道理解题的答案位是:

| 任务 | 答案位(位置号) | 由谁预测(位置号) | 预测的内容 |
|---|---|---|---|
| i2t | 19、20、21 | 18、19、20 | 颜色、动物、`<eos>` |
| a2t | 29、30 | 28、29 | 动物、`<eos>` |
| v2t | 67、68、69、70 | 66、67、68、69 | 颜色、动物、动作、`<eos>` |

「由谁预测」是答案位往前一格:闭标签 `</img>` 那一格的输出负责说颜色,颜色那一格的输出负责说动物,以此类推。这就是普通语言模型的「预测下一个词」。

注意力掩码([sparrow.py:176-180](../code/sparrow.py#L176)):

```python
same = lambda x: (x[:, None] == x[None, :]) & (x[:, None] >= 0)
# 文字只看前面;同一块(整段模态,或 frame 时的一帧)互相都看得见;同一段模态里不同块互相看不见
self.mask = ((i[None, :] <= i[:, None]) & ~same(p)) | same(b)
```

对理解题来说:

- **特征段内部双向**:16 个 `see` 向量互相都看得见;`watch` 的 64 个向量也是一整块(`--vid_attn frame` 只影响 `vid` 那段加噪潜变量,不影响 `watch`)。特征段还能看见它前面的 `<bos>` 和开标签。
- **文字位置因果**:闭标签和答案位只看自己和前面的位置。位置 20(动物)能看见 0~19,包括全部特征和位置 19 填的颜色;看不见 21。

所以「各目标格只读前文」是由掩码保证的。i2t 的完整 22×22 掩码画在 [ep02 docs/02](../../ep02-t2i/docs/02-序列与注意力掩码.md) 里。

## 3. 训练:标准答案填进前文,只在答案位算交叉熵〔ep02 已有 · ep06 首次启用〕

[sparrow.py:543-547](../code/sparrow.py#L543)

```python
else:                                  # 理解题(task 不在 GEN 里)
    tok = fill_tok(lay, slots, B)      # 把标准答案填进 C/A/T 空位
    with torch.autocast("cuda", torch.bfloat16):
        logits, _ = model(lay, tok, segs, None)          # 不加噪,t=None
    loss = F.cross_entropy(logits[:, lay.answer - 1].float().flatten(0, 1), tok[:, lay.answer].flatten())
```

- `fill_tok`([sparrow.py:477-483](../code/sparrow.py#L477))把 `Cache.get` 返回的颜色、动物、动作编号填进空位。理解题不传 `drop`,所以不会把答案换成 `<null>`。
- `logits[:, lay.answer - 1]` 取「答案位往前一格」的输出,i2t 得到 `[B, 3, 27]`,摊平后和 `[B·3]` 个正确编号算交叉熵。
- 这种做法叫 teacher forcing:说动物时,前文里的颜色是**标准答案**,不是模型自己刚说的。一次前向就能同时训练全部答案位。
- `<eos>` 格也算损失。它的正确答案永远是编号 19,很快就学会了;它让模型学会「说完」。

交叉熵对 27 项做 softmax:提高正确项的分数,同时压低其余 26 项(包括 `<vid>` 这类记号)。README 说「推高红色、压低其他项」是当前目标的训练方向示意,混合训练里每一步的梯度来自六种题的总和,所以不能断言某个原始分数每步都单调变化。

一个能对上号的数字:27 项均匀猜的交叉熵是 ln 27 ≈ **3.2958**。主线第 0 步的理解损失是 i2t **3.6372**、a2t **3.7081**、v2t **3.2927**([`reports/train.jsonl`](../reports/train.jsonl) 第 1 行),都在这个值附近或略高,说明训练开始时文字出口基本是在乱猜(见第 5 节)。

## 4. 回答:`describe` 逐格贪心〔ep02 已有〕

[sparrow.py:652-661](../code/sparrow.py#L652)

```python
@torch.no_grad()
def describe(model, lays, task, segs, B):
    """逐词贪心地说出答案:因果注意力保证每个位置只看得见已经说出的词。"""
    lay = lays[task]
    tok = fill_tok(lay, {s: torch.zeros(B, dtype=torch.long, device=dev) for s in lay.slots}, B)
    for p in lay.answer.tolist():
        with torch.autocast("cuda", torch.bfloat16):
            logits, _ = model(lay, tok, [s.float() for s in segs], None)
        tok[:, p] = logits[:, p - 1].argmax(-1)
    return tok[:, lay.answer]
```

逐行说:

1. 空位先全部填 0(编号 0 是「红色」,只是占位)。因为掩码是因果的,位置 p−1 看不见位置 p,所以占位的值不影响当前这一格的预测;等轮到下一格时,前一格已经换成模型自己选的词了。
2. 每一轮跑一次完整前向,取 `p−1` 位 27 项里分数最高的那项填进 `p` 位。没有采样、没有温度、没有束搜索。
3. 循环次数等于答案位个数:i2t 3 次、a2t 2 次、v2t 4 次,和模型说了什么无关。即使中途说出 `<eos>`,也会继续跑完;最后一格就算没说 `<eos>`,也照样返回。
4. 返回全部答案位(含最后的 `<eos>` 格)。`infer.py` 把它们原样打印出来,所以输出是「红色 小猫 `<eos>`」这样的。

每一轮都重算整条序列(没有 KV 缓存)。理解序列最长才 71,重算几次的开销可以忽略。

**没有前缀约束带来的实际后果**:[`samples/lesson/answers.json`](../samples/lesson/answers.json) 最后一条记录了第 5 集权重看同一段红猫向左跑动画的回答:`<vid> 小兔 向右跑 跳`。颜色格选了记号 `<vid>`,`<eos>` 格选了动作「跳」,四格里一个都不对。整题按内容判,第 6 集训练后同一输入的回答是 `红色 小猫 向左跑 <eos>`。

## 5. 为什么 `text_head` 在第 6 集之前从没训过

`forward` 每次都会算 `text_head(h)`([sparrow.py:300](../code/sparrow.py#L300)),但生成题的损失只用 `flow_head` 的输出 `v`:

```python
_, v = model(lay, tok, segs, t)        # 生成题:丢掉 logits
loss = F.mse_loss(v.float(), x1 - eps)
```

logits 被丢掉,不进损失,`text_head` 就收不到梯度。第 2、4、5 集只练生成题,所以:

- `text_head`(10,395 个参数)从第 2 集构造起就没被更新过;
- 理解投影层 `inp.see`、`inp.watch`、`inp.hear` 和 `where.see/watch/hear`、`when.watch` 只在理解题里用到,同样没被更新过;
- `AdamW` 跳过 `grad is None` 的参数,连权重衰减都不做,所以它们停在初值。

能直接验证的证据:`LayerNorm` 初始化时权重全为 1、偏置全为 0。用标准库读两份发布权重里的张量(没用 torch,只解析 `.pt` 里的 zip 和 pickle),结果是:

| 张量 | 第 5 集 `course_ep5/final.pt` | 第 6 集 `course_ep6/final.pt` |
|---|---|---|
| `inp.see.0.weight` | 全为 1.00000 | 0.96199 ~ 1.01725 |
| `inp.see.0.bias` | 全为 0.00000 | −0.01368 ~ 0.01813 |
| `inp.watch.0.weight` | 全为 1.00000 | 0.96295 ~ 1.01697 |
| `inp.hear.0.weight` | 全为 1.00000 | 0.96990 ~ 1.00871 |

第 5 集里三个投影层的 LayerNorm 还是出厂值,第 6 集才动了。`text_head` 用的是 `nn.Linear` 的默认均匀初始化,没有这么醒目的固定值;第 5 集里它的偏置落在 ±0.0465 以内,在初始化范围 ±1/√384 ≈ ±0.0510 之内,和「没训过」一致。第 0 步的交叉熵接近 ln 27,也是同一件事的旁证。

输入一侧略有不同:颜色、动物、动作这 18 个词的 `tok` 嵌入在生成题里当条件,早就训练过;`<eos>`、`</img>`、`</aud>`、`</vid>` 四个记号只出现在理解模板里,第 6 集之前没有收到过来自损失的梯度(`tok` 是整张嵌入表,这几行每步收到的梯度都是 0,只有权重衰减让它们缓慢缩小)。

> **注意 · 这不等于「第 5 集的理解能力是随机的」**:主干(8 层 `Block`)在前几集已经练了很多,本集理解题是从「练过的主干 + 没练过的投影层和文字出口」起步的,不是整体从零开始。理解损失在 100 步内就从 3.6 降到 0.0003(见 [03](03-六任务接续训练.md) 第 4 节),这可能和主干已经练过有关;本集没有做「从零练理解题」的对照,不能下定论。
