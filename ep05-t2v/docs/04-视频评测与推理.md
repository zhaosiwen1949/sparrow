# 04 · 视频评测与推理:怎么判、报告怎么读、怎么自己生成

本篇分两半:前半讲 `evaluate` 里的 t2v 段和第 4 集加的两把尺子(本集第一次跑出数),后半讲 `infer.py t2v`。

## 1. 出题:192 道题〔ep02 已有〕

[sparrow.py:890-895](../code/sparrow.py#L890):

```python
ai = torch.arange(6, device=dev).repeat_interleave(32)               # 6 种动物,各 32 题
ti = torch.arange(4, device=dev).repeat_interleave(8).repeat(6)      # 每种动物里 4 个动作,各 8 题
ci = torch.arange(len(ai), device=dev) % 8                          # 颜色按题号轮换
x = draw("t2v", {"C": ..., "A": ..., "T": ...}, len(ai), size=64)
vids = torch.cat([videos(data.raw(vmod, x[s:e])) for s, e in chunks(len(x), 32)])
```

- 6 动物 × 4 动作 × 8 段 = **192 道题**,8 种颜色轮流出现。
- `draw` 的起点噪声来自 `eval_noise`:第 i 题按种子 `eval_seed*10000+i` 单独生成〔ep04 新增〕。同一个 `--eval_seed` 下,不同权重的第 i 题从同一团噪声出发,这是第 2 篇统一口径的基础。
- 生成每批 64 题,解码每批 32 段,判卷每批 64 段。
- `videos(z)` 按 `vmod` 选解码器〔ep04 新增〕:`vid` 用 Wan VAE,`vidimg` 把 16 帧各自交给 FLUX.2 解码([sparrow.py:834-837](../code/sparrow.py#L834))。

判卷交给 `VideoJudge`,报 `animal_acc`、`color_acc`、`action_acc`,以及三项都对的 `all_acc`。这是本集所有「视频分」的口径。

## 2. 两把尺子:`video_rulers`〔ep04 新增 · ep05 首次跑〕

[sparrow.py:718-728](../code/sparrow.py#L718)。视频判卷器只给一个对错,看不出「画面到底动没动」「每一帧是不是都像那只动物」。第 4 集加了两把尺子:

| 尺子 | 怎么算 | 报告字段 |
|---|---|---|
| 相邻帧变化 | 相邻两帧逐像素通道的均方根误差(0~255),同一动作的各段取平均,得到 15 个点的曲线 | `adjacent_rmse_by_action` |
| 逐帧一致 | 16 帧逐一交给**图判卷器** `ImageJudge`,看动物和颜色对不对;16 帧全对,这一段才算一致 | `frame_acc`(逐帧对的比例)、`frame_consistent`(整段一致的比例)、`frame_acc_by_index`(按帧号) |

相邻帧变化的用法见第 2 篇第 5 节。

## 3. 先量判卷器自己:`video_calibration`〔ep04 新增 · ep05 首次跑〕

[sparrow.py:731-757](../code/sparrow.py#L731)。逐帧一致这把尺子靠的是**图判卷器**,而图判卷器是用静态图训的,未必认得动画里的每一帧。所以每次评 t2v,都先拿同样的尺子量两组参照:

- `real`:全部 500 段测试真动画;
- `roundtrip`:这 500 段「压缩器编码再解码」的往返片(编码用 bf16,和 `encode.py` 一致;解码用 fp32,和评测一致)。

另外,两组都交给视频判卷器判一遍(`judge_vid_all_acc`)。如果图判卷器在真动画单帧上的正确率不到 `VALID_FRAME_ACC = 0.97`,逐帧一致率就标为无效(`frame_consistency_valid: false`)。数字照常输出,只是加上这个标记。同一进程里同一压缩器只量一次(`_calib` 缓存),量完挪回 CPU。

**本集的实测**([`reports/attention_full.json`](../reports/attention_full.json) 的 `eval.t2v.judge_check`):

| | `real`(真片) | `roundtrip`(Wan 往返) |
|---|---:|---:|
| `frame_acc`(图判卷器逐帧) | **0.9088** | 0.8956 |
| `frame_consistent` | 0.694 | 0.630 |
| `judge_vid_all_acc`(视频判卷器) | 1.0 | 1.0 |
| `frame_consistency_valid` | **false**(0.9088 < 0.97) | |

视频判卷器在真片和往返片上都是 100%,可以放心用;图判卷器在真片上只有 90.9%,没过 97% 这条线。按帧号看,`real.frame_acc_by_index` 从首尾的 0.99~1.0 掉到中间第 7~9 帧的 0.744、0.738、0.778。这几帧正好是「跳」的最高点、「转身」压成一条线的时候(见 [01](01-文字到视频全链路.md) 第 1 节),静态图里从来没有这种画面。

所以 README 说:报告中的逐帧一致率标为无效,**不拿它比较优劣**。生成片的这几项数字(例如 full 版 `frame_acc` 0.902、frame 版 0.874)照样写在报告里,但只能当参考。

## 5. report.json 怎么读

本集有两代报告(见 [README](README.md)「本集的实测数字」)。用当前代码写的报告,和视频有关的字段:

| 字段 | 含义 | 本集主要值 |
|---|---|---|
| `seq_len.t2v` | t2v 序列长度 | 325(逐帧表示 1029) |
| `proj_params` | 用到的模态入口投影参数量 | `vid` 6528;`vidimg` 12672 |
| `batch_per_step` / `exposure` | 每步条数 / 总共见过多少条 | t2v 128 / 512000 |
| `train_data.videos` | 训练动画段数 | 10000 |
| `stat_source.vid` | 视频统计量从哪来 | 接续训练:「现算…(本集新加的模态)」;重评:`ckpt` |
| `eval_config` | CFG、采样步数、评测种子、噪声规则 | CFG 3、30 步、种子 0 |
| `eval.t2v.*_acc` | 视频判卷器的分 | 见第 2、3 篇 |
| `eval.t2v.adjacent_rmse_by_action` 等 | 两把尺子 | 见上文第 2 节 |
| `eval.t2v.judge_check` | 判卷器自检 | 见上文第 3 节 |
| `eval_only` | 重评时:评的是哪份权重、它的哈希、它训练时的参数 | `attention_*.json` 才有 |
| `init` | 这次的起点身份与各种哈希 | 见 [ep04 docs/03](../../ep04-t2a/docs/03-随机协议与可复现.md) |

`weights/course_ep5*/report.json` 是较早版本的代码写的,只有 `args`、`params_M`、`seq_len`、耗时、显存、`log` 和 `eval`(t2v 只有四个 `*_acc`)。

> **注意 · `eval_config.noise` 里的提醒**:当前代码的评测噪声按题号生成,旧报告用的是全局种子 1234 的随机数,两者「不能拼在一条曲线上」。这正是第 2 篇「原训练终评」和「统一口径重评」要分开列的原因。

## 6. 自己生成:`infer.py t2v`〔ep02 已有 · ep04 扩充〕

[infer.py](../code/infer.py) 不需要数据、判卷器和缓存,只要 `final.pt` 和 Wan VAE:

```bash
python infer.py ../weights/course_ep5/final.pt t2v '红色 小猫 向左跑' "$W/cat-left.gif"
python infer.py ../weights/course_ep5_frame/final.pt t2v '红色 小猫 向左跑' "$W/cat-frame.gif"
```

流程:

1. `S.load` 读权重,按里面存的 `args` 重建模型和 `Layout`(`vid_attn`、`vid_lat` 都照权重,[sparrow.py:604-612](../code/sparrow.py#L604))。
2. 输入必须正好 3 个词,依次填进颜色、动物、动作三个词槽([infer.py:99-103](../code/infer.py#L99))。词表:颜色 红色/橙色/黄色/绿色/蓝色/紫色/粉色/棕色;动物 小猫/小狗/小兔/小鸟/小鱼/小熊;动作 向左跑/向右跑/跳/转身。
3. 检查权重里有没有 `vid` 的归一化统计量。本集权重有;第 2、4 集的权重没有,要用 `--stat_from` 从别的权重借,否则退出。
4. 起点噪声:默认 `start_noise(lay, 1, seed)`,`--seed` 默认 0;或者用 `--noise 文件.pt` 指定一团存好的噪声。
5. `generate`(默认 30 步、CFG 3,可用 `--steps`、`--cfg` 改)→ `denorm` → `VideoVAE.decode`;`vidimg` 权重改为逐帧 FLUX.2 解码([infer.py:128-131](../code/infer.py#L128))。

输出〔ep04 新增的部分带 ★〕:

| 文件 | 内容 |
|---|---|
| `<输出>.gif` | 16 帧,每帧最近邻放大到 256×256,100 ms 一帧 |
| ★ `<输出>.noise.pt` | 这次的起点噪声,`[1, 320, 16]`;下次 `--noise` 传回来就能复现 |
| ★ `<输出去扩展名>_frames/frame_00..15.png`、`frames.npy` | 64×64 原尺寸逐帧 |
| ★ `--record 文件` | 追加一行 JSON:权重哈希、输入、噪声、CFG、步数 |

**和仓库里的 GIF 对不上是正常的。** README 第 3 节说明:直接推理显示为 256×256,而评测样例是 192×192;`samples/course_ep5/` 是原训练终评用旧的抽噪声顺序生成的,起点噪声也不一样。不过当前代码里,`start_noise(lay, 1, 0)` 和 `eval_noise` 第 0 题(`eval_seed=0`)用的是同一个种子 0,所以 `infer.py --seed 0` 生成「红色 小猫 向左跑」时,和 `samples/attention_full/gen_t2v_0_红色小猫向左跑.gif` 的**起点噪声相同**,画面应当基本一致;仍不承诺逐字节相同(尺寸不同,批量大小也不同)。

本集权重只能用来生成动画(t2v)、画图(t2i)、念名字(t2a)。看图、听声、看视频这几项没练过,也没有对应的统计量。
