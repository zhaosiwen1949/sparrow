# 02 · 时间槽与注意力掩码:帧与帧要不要互看

README 第 4 节的对照是:同一份第 4 集参数,分别用 `--vid_attn full` 和 `--vid_attn frame` 训 4000 步,看动画会不会变差。本篇讲这个开关在代码里改了什么,以及应该怎么读那几组数字。

掩码的一般原理(`seg`、`block`、`same`)在 [ep02 docs/02](../../ep02-t2i/docs/02-序列与注意力掩码.md) 里已经讲过,这里只讲视频。

## 1. 「帧」其实是时间槽〔ep02 已有〕

代码和注释里说的「帧」,在 t2v 里指的是 **Wan VAE 压缩后的时间槽**,不是原始的 16 帧画面:

- 原始 16 帧 → 末尾复制一帧凑 17 帧 → Wan VAE → **5 个时间槽**,每槽 8×8 = 64 个向量(见 [01](01-文字到视频全链路.md) 第 3 节);
- 第 0 槽只管第 0 帧,之后每槽管 4 帧;
- 视频段共 5 × 64 = 320 个向量,加 5 个文字位,序列长 325。

所以 `frame` 模式下「每帧只看自己」的准确说法是:**每个时间槽只看自己这 64 个向量,外加前面的 5 个文字**。

## 2. `Layout` 怎么切块〔ep02 已有〕

[sparrow.py:157](../code/sparrow.py#L157)、[sparrow.py:178-180](../code/sparrow.py#L178):

```python
block += [len(self.pieces) * 100 + (j // per if frame else 0) for j in range(n)]
...
same = lambda x: (x[:, None] == x[None, :]) & (x[:, None] >= 0)
# 文字只看前面;同一块(整段模态,或 frame 时的一帧)互相都看得见;同一段模态里不同块互相看不见
self.mask = ((i[None, :] <= i[:, None]) & ~same(p)) | same(b)
```

- `per = MODS["vid"][1] = 64`,所以 `j // per` 就是第几个时间槽(0~4)。
- `full`:整段 320 个向量同一个块号,段内双向全看见。
- `frame`:5 个块号,`~same(p)` 先把整段里的因果关系挖掉,`same(b)` 只补回同一个槽内的,槽与槽之间就看不见了。
- 两种模式下视频位置都看得见前面的文字(颜色、动物、动作),因为文字和视频不在同一段,走的是「只看前面」那一项。

用 5 个文字 + 5 个槽画一张缩略图(每个槽取一个代表位置,■ 表示看得见):

```text
默认 full                              frame 模式
         文字 s0 s1 s2 s3 s4                    文字 s0 s1 s2 s3 s4
 文字(5)   ■   ·  ·  ·  ·  ·          文字(5)   ■   ·  ·  ·  ·  ·
 s0        ■   ■  ■  ■  ■  ■          s0        ■   ■  ·  ·  ·  ·
 s1        ■   ■  ■  ■  ■  ■          s1        ■   ·  ■  ·  ·  ·
 s2        ■   ■  ■  ■  ■  ■          s2        ■   ·  ·  ■  ·  ·
 s3        ■   ■  ■  ■  ■  ■          s3        ■   ·  ·  ·  ■  ·
 s4        ■   ■  ■  ■  ■  ■          s4        ■   ·  ·  ·  ·  ■
```

`frame` 只改 `block`,不改序列长度,也不改参数。掩码是一张 `[325, 325]` 的布尔矩阵,原样交给 `scaled_dot_product_attention`,计算量和 `full` 一样。所以两版的参数量都是 16.04M,训练耗时也几乎相同(1074.2 秒对 1074.3 秒,出自两份 `weights/*/report.json`)。

`vid_attn` 写进 `final.pt` 的 `args`,`load`([sparrow.py:611](../code/sparrow.py#L611))和 `--eval_only` 都按它重建 `Layout`。所以拿 `course_ep5_frame` 推理或重评时,掩码会自动是 `frame`。

## 3. 「只看自己」也不是完全没有跨帧信息

两个原因:

1. **Wan VAE 本身跨时间**。它的编码器、解码器都是时空卷积(因果的),解码时相邻槽会互相影响。主干里槽与槽看不见,解出来的画面仍然不是 5 段互不相干的片段。
2. **时间位置 `when.vid` 还在**([sparrow.py:279](../code/sparrow.py#L279))。每个槽知道自己是第几个,加上文字里有动作词,它可以「各自按时间表演」,但没法看邻居现在演到哪了。

所以这组对照只能说明「**主干里**槽与槽互看」有没有用,不能说成「整个模型完全没有跨帧信息」。

## 4. 两种口径的数字〔ep05 首次启用〕

视频分是 192 道题由 `VideoJudge` 判动物、颜色、动作,三项都对才算对。

| 口径 | 互看(full) | 只看自己(frame) | 出处 |
|---|---:|---:|---|
| 原训练终评 | 99.5%(191/192) | 95.8%(184/192) | `weights/course_ep5*/report.json` |
| 统一口径重评 | 99.5%(191/192) | 97.4%(187/192) | `reports/attention_full.json`、`attention_frame.json` |

为什么有两种口径:

- **原训练终评**是用较早版本的代码写的。它的起点噪声是按全局种子顺序抽的,抽到第几题取决于前面的任务用了多少随机数。
- **统一口径**是用当前代码 `--eval_only --ckpt ... --eval_tasks t2v --eval_seed 0` 重评同两份权重:每道题的起点噪声按 `eval_seed*10000+i` 单独生成([sparrow.py:624-626](../code/sparrow.py#L624)),两份权重的第 i 题从**同一团噪声**出发。片中采用的是这一组。

两种口径不能混用。各项拆开看,差距全在动作上(颜色只在原终评的 frame 版错了 1 道):

| | full 原终评 | frame 原终评 | full 重评 | frame 重评 |
|---|---:|---:|---:|---:|
| `animal_acc` | 1.0 | 1.0 | 1.0 | 1.0 |
| `color_acc` | 1.0 | 0.9948 | 1.0 | 1.0 |
| `action_acc` | 0.9948 | 0.9635 | 0.9948 | 0.9740 |

训练损失也是 frame 版高:第 3900 步 t2v 损失 full 0.0896、frame 0.1258(两份 report 的 `log`)。

## 5. 相邻帧变化:槽交界处的跳变

统一口径的报告里,`eval.t2v.adjacent_rmse_by_action` 按动作记录 15 对相邻帧的像素变化(每像素通道均方根误差,0~255,对该动作的 48 段取平均)。`judge_check.real` 是同一把尺子量 500 段真动画的结果。这把尺子怎么算见第 4 篇。

「向左跑」在槽交界处(第 0→1、4→5、8→9、12→13 帧)的值,出自 [`EXPERIMENTS.md`](../EXPERIMENTS.md):

| 版本 | 0→1 | 4→5 | 8→9 | 12→13 |
|---|---:|---:|---:|---:|
| 真片 | 25.581 | 25.343 | 25.627 | 25.635 |
| 互看 | 26.569 | 26.480 | 27.306 | 27.740 |
| 只看自己 | 40.176 | 37.748 | 42.001 | 41.113 |

再对照**槽内**的相邻帧(例如 1→2、2→3、3→4),frame 版的「向左跑」是 28.46、27.944、27.339,和 full 版(27.521、27.745、27.583)差不多。也就是说,frame 版在一个槽内部是连贯的,变化集中出现在槽与槽的交界处:每个槽各自去噪,相邻槽对不齐,画面就会跳一下。其他动作也一样,例如「转身」的 0→1:真片 4.6、full 11.16、frame 31.048。

[`EXPERIMENTS.md`](../EXPERIMENTS.md) 特意提醒:这些值只描述本次样例的变化,**不能把像素变化小直接当成动画更好**(画面完全不动,变化也是 0)。

## 6. 本集怎么跑这组对照

命令出自 README 第 4 节(本仓库的 VS Code 配置里也有对应入口):

```bash
# 只看自己版:从同一份第 4 集参数另训一份
python sparrow.py ... --out "$W/runs/course_ep5_frame" --init "$INIT" --tasks t2i,t2a,t2v \
  --steps 4000 --seed 0 --rng legacy --vid_attn frame --eval_every 0

# 统一口径重评两份已发布参数
python sparrow.py ... --out "$W/runs/attention_full"  --eval_only \
  --ckpt ../weights/course_ep5/final.pt       --eval_tasks t2v --eval_seed 0
python sparrow.py ... --out "$W/runs/attention_frame" --eval_only \
  --ckpt ../weights/course_ep5_frame/final.pt --eval_tasks t2v --eval_seed 0
```

两版都用 `--rng legacy`、种子 0、同一份 `--init`,所以起点权重和每步抽到的样本都相同,只差掩码这一处。`--eval_only` 时的结构、随机协议和训练子集一律照权重里存的 `args`([sparrow.py:1083-1092](../code/sparrow.py#L1083)),命令行不用再写 `--vid_attn`。
