# 02 · 接续训练与旧题回放

第 4 集不从零训练,而是用 `--init ../../ep02-t2i/weights/final.pt` 接着第 2 集的权重往下练。本篇讲接续时第 4 集补上的三件事:

1. **结构从权重里重建**:`DEFAULTS` / `with_defaults` / `configure`。
2. **归一化统计量要继承,不能现算**:`Cache` 的三种模式。
3. **旧题回放**:`--bs_task` 控制每轮带几道画图题,外加几个中途评测相关的开关。

## 1. 结构参数存进权重,读回时补默认值〔ep04 新增〕

[sparrow.py:70-91](../code/sparrow.py#L70)

```python
# 结构与训练子集的参数:训练时写进 final.pt,--init / --eval_only / load 照它重建;旧权重没有的键按这里的默认值
DEFAULTS = {"dim": 384, "depth": 8, "heads": 6, "aud_split": 4, "vid_attn": "full", "maxlen": 400, "watch_frames": 16,
            "see_from": "see", "vid_lat": "vid", "per_combo": 0, "hold": "", "match_total": False, "voices": 0, "voice_draw": 0,
            "clips": 36}


def with_defaults(args):
    return {**DEFAULTS, **{k: v for k, v in args.items() if v is not None}}


def configure(a):
    split_audio(a["aud_split"])
    MODS["watch"] = (768, 4, a["watch_frames"], False)
    if a["see_from"] == "img": ...          # 可选表示,见 06
    if a["vid_lat"] == "vidimg": ...
```

`final.pt` 一直把训练时的全部命令行参数存在 `ck["args"]` 里。第 2 集的 `load` 只读 `aud_split`、`dim`、`depth`、`heads` 这几项;第 4 集多了一批会改变模型形状或训练数据的参数(`maxlen`、`watch_frames`、`see_from`……),第 2 集训出的旧权重里没有这些键。于是:

- `with_defaults` 先铺一层默认值,再用权重里的值覆盖。旧权重缺的键按默认值处理,正好就是旧权重训练时的样子。
- `configure` 按这份参数改全局的 `MODS` 和 `TEMPLATES`,保证 `Sparrow(...)` 建出来的形状和权重对得上。

用到这一对函数的地方有三处:[`load`](../code/sparrow.py#L604)(给 infer.py 用)、`main` 里的 `--init`,以及 `--eval_only --ckpt`。

`--init` 时会核对结构:`dim`、`depth`、`heads`、`aud_split`,外加新增的 `maxlen`,任何一项不一致就直接退出([sparrow.py:1113-1116](../code/sparrow.py#L1113))。加载用的是 `strict=False`,但只允许缺「上一集没有的可选表示」(`seelat`、`vidimg` 相关参数);缺了别的、或者多出参数,都报错退出([sparrow.py:1118-1123](../code/sparrow.py#L1118))。

> 第 2 集→第 4 集不会遇到「缺参数」的情况:第 2 集的权重里本来就有 `inp.aud`、`flow_head.aud`、`where.aud`(见 [01 第 4.1 节](01-文字到声音全链路.md#41-拆成-104-个向量))。

## 2. 归一化统计量:继承上一集,不现算〔ep04 新增〕

### 2.1 问题在哪

每种向量进主干前,要逐维减均值、除以标准差;这组 `[mean, std]` 跟权重一起存在 `final.pt` 的 `stat` 里。

第 2 集的 `Cache.__init__(path, mods)` **每次都按这次的训练数据重新计算**统计量,`--init` 时也一样。只要数据不变,算出来就和上一集相同,所以平时看不出问题。可一旦训练子集变了(比如只用一部分训练图,见 06),或者缓存是另一次编码的结果,同一个 `img` 就会得到不同的统计量。这时上一集学到的「img 向量长什么样」就和这一集喂进去的数据对不上了。

### 2.2 三种模式

[sparrow.py:360-452](../code/sparrow.py#L360),docstring 已经写得很清楚:

| 调用方式 | `stat` | 行为 |
|---|---|---|
| 从零训 | `None` | 全部按这次的训练子集现算 |
| `--init` 接着训 | 上一集的 `stat`,`strict=False` | 上一集权重里有的照搬(形状不对就报错);**上一集本来就用过、权重里却没有统计量的模态**直接报错;只有本集新加的模态才现算 |
| `--eval_only --ckpt` | 那份权重的 `stat`,`strict=True` | 要用的每种模态都必须在 `stat` 里且形状正确,缺一样就报错 |

「上一集本来就用过」的判断来自 [`task_mods` / `run_mods`](../code/sparrow.py#L346):

```python
inherited = run_mods(with_defaults(parent["args"])) if a.init else ()    # 上一集 tasks + eval_tasks 用到的全部模态
```

第 2 集的权重只训、只评了 t2i,所以 `inherited = {"img"}`。第 4 集要用 `img` 和 `aud`:`img` 照搬,`aud` 现算。这一结果会写进 report.json 的 `stat_source`,`replay_0` 的记录如下:

```json
"stat_source": {"aud": "现算:训练录音 1296 行(本集新加的模态)", "img": "ckpt"}
```

> 为什么上一集用过、权重里却没存统计量时要报错,而不是悄悄现算一份顶上?因为现算出来的未必和上一集训练时的一样。宁可停下来,也不让模型在不知情的情况下吃到另一种尺度的数据。

### 2.3 同一份缓存,不同统计量

[sparrow.py:434-445](../code/sparrow.py#L434) 处理一种边角情况:两种模态读同一份缓存字段(比如 06 里的 `seelat` 和 `img` 都读 `img_lat`)。统计量逐元素相同,就共用一份归一化后的数据;不同,就各存一份,键名写成 `img_lat@seelat`。`self.key[模态]` 记录每种模态该去哪个键取数据,所以 `Cache.get` 和 `evaluate` 里都改成了 `tr[key[...]]`。本集只用 `img` 和 `aud`,不会触发这种情况。

## 3. 旧题回放:`--bs_task`〔ep04 新增〕

### 3.1 为什么要带旧题

如果只练念名字(`--tasks t2a`),画图会被遗忘。第 4 集的对照数据(出自 [EXPERIMENTS.md](../EXPERIMENTS.md) 4-2):

| 每轮画图题 / 念名字题 | 画图正确率 | 念名字正确率 |
|---|---:|---:|
| 0 / 512(只练念名字) | 0.8%(3/384) | 97.9%(235/240) |
| 512 / 512(两样一起练) | 100.0%(384/384) | 98.3%(236/240) |

主线因此用 `--tasks t2i,t2a`。那么每轮带几道画图题才够?这需要能单独设定 t2i 的批大小。

### 3.2 实现

[sparrow.py:489-491](../code/sparrow.py#L489)

```python
def batch(a, task):
    """这个任务每步取几条:--bs_task 单独给的优先,否则视频两样用 --bs_vid、其余用 --bs。"""
    return a.bs_task[task] if task in a.bs_task else (a.bs_vid if task in ("t2v", "v2t") else a.bs)
```

`--bs_task "t2i=51"` 解析成 `{"t2i": 51}`,并检查必须是正整数([sparrow.py:1079-1081](../code/sparrow.py#L1079))。想不练某个任务,就别把它写进 `--tasks`,而不是把批大小设成 0。`train` 里原来的 `B = a.bs_vid if ... else a.bs` 改成了 `B = batch(a, task)`。

report.json 多了两项记录:

- `batch_per_step`:每个任务每步取几条,比如 `{"t2i": 512, "t2a": 512}`。
- `exposure`:批大小 × 步数,即整个训练里每个任务一共见过多少条样本,比如 `{"t2a": 4096000}`。

> **注意**:画图的损失权重始终是 1,念名字是 4。所以「每轮带 10 道画图题」不等于「把 2% 的力气花在复习上」;EXPERIMENTS 里也特意写了这一点。

### 3.3 4-3 的结果

```bash
for N in 10 26 51 128 256 512; do
  python sparrow.py ... --out "$W/runs/replay_$N" --init "$INIT" --tasks t2i,t2a --bs_task "t2i=$N" \
    --steps 8000 --seed 0 --rng paired --eval_every 1000
done
```

| 每轮画图题 | 画图正确率 | 念名字正确率 |
|---:|---:|---:|
| 10 | 100.0% | 95.0% |
| 26 | 100.0% | 98.8% |
| 51 | 100.0% | 97.5% |
| 128 | 100.0% | 96.2% |
| 256 | 100.0% | 97.1% |
| 512 | 100.0% | 98.3% |

每轮只带 10 道画图题,也保住了画图;各档念名字的正确率在 95% 到 99% 之间,每档只跑了一个种子,看不出差别。这组对照用 `--rng paired`,改动 t2i 的批大小不会影响 t2a 抽到的样本(见 [03](03-随机协议与可复现.md))。

## 4. 中途评测相关的开关〔ep04 新增〕

| 参数 | 作用 | 实现 |
|---|---|---|
| `--eval_every N` | 第 2 集就有:每 N 步评一次 | 现在并入 `a.eval_points` |
| `--eval_at 25,50,75` | 另外在这些步评测,和 `--eval_every` 取并集 | [sparrow.py:1095-1096](../code/sparrow.py#L1095) |
| `--keep_midway` | 中途评测时另存当时的 EMA 权重 `step<N>/final.pt`,infer.py 能直接用 | [`midway`](../code/sparrow.py#L580) 里调 [`save`](../code/sparrow.py#L575) |
| `--stop_at K` | 学习率仍按 `--steps` 排,练到第 K 步就停下、存权重、评测。用来原样重走某次运行的前一段 | `train` 的循环上限改为 `stop_at or steps` |

`train` 里判断「到点评测」的条件,从 `(step+1) % eval_every == 0` 改成了 `step + 1 in a.eval_points`([sparrow.py:560](../code/sparrow.py#L560))。中途评测的时间和显存都不算进训练:显存峰值在评测前后各清零一次,单独记为 `midway_eval_peak_mem_GB`(见 [03](03-随机协议与可复现.md))。`midway` 还会把 CUDA 和 CPU 的随机数状态存下来、评完恢复,第 2 集就是这样做的;第 4 集给它补了没卡时的分支。

|---|---:|---:|---:|---:|---:|---:|---:|---:|

## 5. 主线命令逐项对照

```bash
python sparrow.py --data "$W/data" --cache "$W/cache" --judges "$W/judges" \
  --out "$W/runs/course_ep4" --init "$INIT" --tasks t2i,t2a \
  --steps 8000 --seed 0 --rng legacy --eval_every 1000
```

| 参数 | 第 2 集有吗 | 说明 |
|---|---|---|
| `--init "$INIT"` | 有 | 第 4 集多了统计量继承和结构核对 |
| `--tasks t2i,t2a` | 有 | 两样一起练 = 512/512 档回放 |
| `--steps 8000` | 有 | 第 2 集主线是 4000 步 |
| `--seed 0` | **新增** | 第 2 集写死为 `torch.manual_seed(0)` |
| `--rng legacy` | **新增** | 主线和九月那次训练用同一个随机协议;对照实验用 `paired` |
| `--eval_every 1000` | 有 | 给 4-4 的进度表 |
| `--weights` | 有(默认 `t2a=4`) | 没写就用默认值 |

主线训练耗时 1584.5 秒,训练显存峰值 7.07 GB(出自 `weights/course_ep4/report.json`)。
